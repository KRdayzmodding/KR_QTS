# Известные баги

Список того, что найдено, воспроизведено и ещё не исправлено. Порядок — по
тяжести: сверху то, что оставляет человека без выхода.

---

## 1. Мод карты, набранный руками, становится неубираемым блокиратором запуска

**Как выглядит.** Проверка перед запуском пишет «Найдены критические проблемы —
запуск невозможен: ✖ Мод не найден: STALKER- DayZone - Map». Мод при этом стоит
в списке модов, галка на нём есть, папка на месте. Убрать проблему из окна
нечем: кнопки только «Отмена» и заблокированная «Запустить».

**Что происходит на самом деле.** В пресете лежат два имени одного и того же
мода:

```json
"mods": [ "STALKER- DayZone - Map",     // призрак, такого мода нет
          "STALKER: DayZone | Map" ]    // настоящий, из meta.cpp подписки
```

Призрак берётся из поля «Моды карты» окна «Своя карта»: там свободный текст,
`CustomMapDialog.result_entry()` принимает набранное как есть, а
`preset_editor._attach_map_mods()` дописывает строку в `preset.mods`, ни с чем
не сверяясь. Опечатка в знаках препинания — а в именах модов мастерской
двоеточия и вертикальные черты обычное дело — превращается в запись, которой не
соответствует ни один мод.

**Почему выхода нет.** Дерево модов строится из реестра
(`ModsPanel._rebuild()` идёт по `registry.all()`), поэтому имя, которому не
соответствует ни один мод, в списке не показывается. Снять галку негде: галки
нет. Убрать мод из «Своей карты» тоже не помогает — `_attach_map_mods()` только
добавляет, никогда не удаляет, и строка остаётся в пресете навсегда. Лечится
только правкой json руками при закрытом приложении.

**Как чинить.**

1. **Мод карты выбирается из существующих, а не набирается.** Поле «Моды карты»
   заменить на выбор из библиотеки модов. Программа знает все установленные моды
   по именам; заставлять набирать идентификатор руками — значит гарантировать
   опечатку, у которой цена «запуск невозможен».
2. **`_attach_map_mods()` сверяется с реестром** и складывает имена по ключу
   папки (`mods.as_folder`), а не по строке. Тогда «STALKER: DayZone | Map» и
   любое его написание — один мод, а не два, и дубль в пресет не попадает.
3. **Из проверки перед запуском должен быть выход.** У строки «Мод не найден» —
   кнопка «Убрать из пресета». Сообщать о тупике и не давать из него выйти —
   худшее, что может сделать проверка: она для того и есть, чтобы человек мог
   запуститься, а не чтобы объяснить, почему не может.

Найдено 10.09.2026 на пресете `KR_404_dz_map`.

## 2. Значение из одних пробелов в редакторе конфига неотличимо от пустого

**Как выглядит.** В конфиге сервера `password = " ";` — один обычный пробел.
Для DayZ это пароль, и клиент при входе его требует. В редакторе конфига поле
выглядит пустым: пробел в однострочном поле не видно ничем. Человек открывает
редактор, убеждается, что пароль стёрт, и не понимает, почему сервер всё ещё
спрашивает пароль. Догадаться можно только заглянув в файл шестнадцатеричным
редактором.

**Чего в этом нет.** Сам редактор такое значение не пишет: при сохранении текст
обрезается (`ui/cfg_editor.py`, `value()` возвращает `text().strip()`), а в
шаблоне `data/serverDZ_template.cfg` стоит `password = ""`. Пробел появляется
при правке файла руками или другим инструментом. Но показать его — наша работа:
редактор для того и открывают, чтобы увидеть, что в конфиге на самом деле.

**Как чинить.** При чтении конфига значение, состоящее из одних пробелов,
показывать не как пустое: либо нормализовать в пустое сразу при загрузке (и
сохранить файл), либо пометить строку — «значение из пробелов, для сервера это
непустое значение». Отдельно стоит предупреждать в проверке перед запуском:
пароль из пробелов почти наверняка означает «хотели стереть, но не стёрли».

Найдено 17.09.2026 на конфиге `Project404_dz_map.cfg`.
